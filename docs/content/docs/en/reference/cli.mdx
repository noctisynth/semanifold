The installed binary is named `smif`; `semifold` is an equivalent long name. Run `smif <command> --help` for the complete options accepted by one command.

<Availability status="released">
  This reference sample is checked against the public command surface of <strong>Semifold 0.3.0-rc.5</strong>.
</Availability>

## Syntax

```text
smif [OPTIONS] [COMMAND]
```

## Commands

| Command | Purpose | Mutates state by default |
| --- | --- | --- |
| `commit` (`add`) | Create one changeset from selected packages, bump levels, tags, and summary paragraphs. | Yes |
| `init` | Discover packages and initialize `.changes/config.toml`; optionally generate GitHub Actions workflows. | Yes |
| `config` | Migrate configuration or synchronize discovered packages with the current config. | Depends on subcommand |
| `status` | Calculate and display the pending release plan. | No |
| `version` | Calculate, prepare, and apply package version, dependency, changelog, and changeset edits. | Yes |
| `publish` | Build and execute the dependency-ordered publish plan. | Yes |
| `ci` | Run Semifold's version or publish CI workflow orchestration. | Yes |
| `mcp` | Start the Model Context Protocol server. | Tool-dependent |

## Global options

| Option | Meaning |
| --- | --- |
| `--dry-run` | Enable preview execution. Mutating Semifold file, registry, and Forge effects are skipped. Read-only registry preflight and commands configured with `dry-run = true` may still run. |
| `--debug` | Show additional diagnostic output. Sensitive configuration values are not part of the public debug contract. |
| `-h`, `--help` | Print help for the selected command level. |
| `-V`, `--version` | Print the Semifold binary version. |

## Common commands

### Initialize one ecosystem

For local use, start with the interactive command:

```bash
smif init
```

CI and environments without interactive input can provide the same answers explicitly:

```bash
smif init --resolvers rust \
  --base-branch main \
  --release-branch release \
  --default-tags \
  --github-actions
```

Use `--no-resolvers`, `--no-default-tags`, or `--no-github-actions` when explicitly choosing the corresponding empty behavior. Use `config sync` when an initialized workspace gains or loses packages.

### Create a changeset

For local use, let the prompts collect the package, bump, tag, and summary:

```bash
smif commit
```

Automation can provide those values as flags:

```bash
smif commit \
  --name add-api \
  --package my-package=minor \
  --tag feat \
  --summary "Add the public API."
```

`--package PACKAGE=LEVEL` and `--summary` are repeatable. When a package omits `=LEVEL`, `--level` supplies the default. Choose either `--tag TAG` or `--no-tag` for a fully non-interactive command.

### Inspect and version

```bash
smif status
smif version --dry-run
smif version
```

`version` rejects a dirty worktree unless `--allow-dirty` is explicitly present. That option accepts the current diff as an input; it is not a general fix for unrelated changes.

### Preview and publish

```bash
smif publish --dry-run
smif publish
```

`publish --allow-dirty` permits publishing from a dirty worktree. `publish --github-release` creates per-package GitHub Releases according to configuration and is available only in the CI environment.

## Exit and output behavior

Human-readable output adapts to TTY, CI, Unicode, and `NO_COLOR`. Non-TTY output is stable and does not contain cursor-control sequences. A publish failure returns a non-zero exit status while preserving a structured report of succeeded, skipped, failed, and not-started packages.

GitHub Actions workflows can opt into versioned structured outputs from `version` and `publish`; those outputs are derived from the same release context, publish plan, and publish report used by the command rather than being reconstructed afterward.
